## 方法

- 同一台 macOS 客户端、Chrome 147，无人工网络/CPU 降速，顺序执行 HTTP 和浏览器测量。
- 桌面 1440×1000、移动视窗 390×844。移动数据是桌面 Chrome 的移动模拟，不代表真实低端手机。
- 三个样本曲目：小汤 1「请弹吧（右手）」4 小节；跨文件「滑稽面孔」16 小节；哈农「练习一」29 小节、391 个 SVG 音符节点。
- 每场景三次，报告中位数。冷访问使用新浏览器上下文；仅继承匿名在线人数租约，HTTP 缓存不继承。暖访问在同一曲目切换到简谱后再次打开原谱。
- 两种操作条件：简谱出现后立即点击；阅读约 3 秒后点击。预加载条件单独列出，不能把预加载时间算作消失。
- 完成标准：点击事件起算，完整 SVG 出现、加载提示消失、两帧绘制后，实际点击放大并验证缩放显示 108%。`clickToPaintMs` 与 `interactiveMs` 分开记录；最终用户耗时采用后者，包含自动化验证开销。
- 原始数据包含资源开始/结束、传输字节、XML 解析/序列化、主线程长任务、音符数量与报错。资源时刻以点击为零点，负值代表点击前预取。

## 瓶颈与实现

1. 首次引擎下载占主要耗时。基线短曲原谱点击至绘制约 2.56 秒，XML 下载约 34 毫秒，解析不足 1 毫秒，OSMD 下载约 2.42 秒。长内容再叠加排版计算。
2. 原实现等 XML 拼接后才下载 OSMD。现在在原谱按钮可见、hover、focus、pointerdown 时准备当前曲目依赖；实际点击仍并行启动。首页、章节目录不预取整个教材或排版引擎。
3. JS/CSS 构建时生成 Brotli 11/gzip 9，HTTP 沿用现有协商、ETag、HEAD、304 逻辑。OSMD 的 Brotli 体积由 333,191 字节降至约 271 KB。压缩只发生在构建阶段，适配 2C2G 服务。
4. 压缩旁文件以实际源内容 SHA-256 命名，避免构建文件写入顺序及同 URL 更新时误用旧内容。服务端摘要缓存限制为 64 个条目，源文件元数据变化后重算；普通谱面和私有文件不使用这些旁文件。
5. 只保留当前曲目已经打开的原谱实例。切换视图复用 SVG，切曲/离开阅读器/切换账号时释放。ResizeObserver 只在可见容器宽度变化时重排，支持目录收起及横竖屏，卸载时断开观察。
6. 预取只复用已有原始 XML Promise 缓存；个人校对与拼接内容仍在打开时读取，不新建按 URL 的个人内容缓存。既有校准、发布、软删除清缓存入口继续有效。失败可以重新加载。
7. 保留有界 User Timing：`panio:original:source/resources/parse/render`，不记录账号、曲名或谱面内容。

## 验证

- 190 项 Vitest、32 项 Node 测试通过；类型检查、lint、生产构建通过。
- 新增行为检查：预取去重、预取失败后恢复、校准清缓存后相同 URL 的新 XML；预压缩解码一致、编码质量权重/q=0、HEAD/304、源内容更新与私有缓存隔离。
- 视觉回归额外覆盖小汤 2「上学的日子」、拜厄 56 小节「三手练习（一）」。桌面/手机共 10 组 SVG 几何属性和文字 SHA-256 摘要与上线前完全一致，音符数为 4、33、52、238、391。原谱标题、缩放、上下曲、刷新与目录展开/收起通过；切回原谱的 DOM 完全复用。
- 首屏/直达/站内返回等入口与上线后的公网数据一并保存在附件。
- 上线后单次入口检查：桌面/手机首页分别 1862/1087 毫秒，站内进入曲目 123/124 毫秒，返回已访问曲目均 18 毫秒，刷新均 261 毫秒；该组无优化前同条件基线，仅说明当前值。首页的 OSMD 请求数为零。

## 已有问题

基线现网 `hanon.segment.039`（343 小节）与 `hanon.segment.063`（96 小节）原谱会在 OSMD 排版中失败，不能作为成功加载耗时样本。已观察到 `findGraphicalNoteFromNote` 连线异常；尝试不可见休止符占位后还会触发 `calculateSingleOctaveShift` 异常，因此未保留该试验，也未删改音符/连线以掩盖问题。这两个条目的原始导入数据/引擎兼容性仍需另行校对，不能声称全库所有条目均可显示。

浏览器控制台中的访客 `/api/v1/auth/me` 401 为正常鉴权结果，与原谱加载错误区分统计。
